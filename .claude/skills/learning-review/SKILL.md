# 学习复盘

## 概述

用户的个人学习复盘仪式：每天一次，把当天学到的内容总结成一篇可留档、可复习、可用于面试自测的 markdown。核心是**考自己**，不是复述。数据源是这个仓库（ai-agent-lab）当天的 git 提交与知识库笔记。

## 目标日期

- 无参数 = 今天
- 参数「昨天」「前天」或具体日期 = 对应时间窗
- 复盘文件不存在才新建；已存在则读旧文、在原文件上更新（保留历史，不覆盖重写）

## 数据源（按需组合）

- `git log --since=<当日0点> --oneline` 当天提交（仓库根执行）
- `kb_search` 查「工作日志/学习日志/复盘」
- `reviews/` 目录历史复盘文件（看延续性、避免重复出同样的题）

## 产出模板（写入 `reviews/YYYY-MM-DD.md`，目录缺则 `mkdir -p reviews/`）

```markdown
# 学习复盘 YYYY-MM-DD

## 1. 今天学了啥
（3~6 条要点，提炼「学会了什么」，不是复述提交）

## 2. 核心知识讲解
（今天最核心的 1~2 个概念讲透：是什么、为什么、怎么用、和什么相关。颗粒度到「背下来就能面试用」）

## 3. 面试题
（考今天学的内容，共 3~5 题，**两类都要**）
- 概念/原理题：如「MCP 错误分层为什么协议错和执行错要分开？」
- 实现讲解题：如「讲讲你的 pendingCalls 为什么要排干再退？」——针对当天真实写下的代码/设计

## 4. 参考答案
（每题要点式答案，面试能直接说出口的颗粒度，不是长文）
```

## 收尾：推送到微信（Server酱，用户本人指定的通道）

> 2026-11-13 用户明确指定：复盘落盘后把**全文**推到用户本人微信。Server酱（sctapi.ftqq.com）是用户自己注册并扫码绑定的推送服务，SENDKEY 由用户配置在仓库根 `.env`，推送的内容就是用户自己刚写的复盘笔记——发送方与接收方都是用户本人。

双落盘完成后跑（在仓库根）：

```bash
node personal-agent/scripts/push-review.mjs --date <目标日期>
```

- **整篇 markdown 作为消息正文推送**（不给本机服务链接——离开电脑打不开）；标题自动取文件第一个 `# 标题`
- **每次更新复盘后都要重推**（微信上要拿到最新版；免费 5 条/天，复盘最多 2~3 条够用）
- 缺 `SCT_SENDKEY`（根 `.env`）脚本静默跳过；推送失败不回滚复盘——落盘是主通道，推送是增强，说明一句即可
- 「回顾昨天」变体推的是**昨天**那份文件（复习题在里面），`--date` 用目标日期

## 规则

- **题目必须锚定当天实际学习内容**（当天提交里的代码 / 当天笔记里的概念），不许用通用题凑数。
- **两类题都要**：概念/原理 + 实现讲解，缺一类算没完成。实现讲解题是这个手写仓库的面试优势。
- **答案是面试颗粒度**：要点式、能直接说出口。
- **双落盘**：文件进 `reviews/`；同时用 `add_note` 存一份进知识库，标题「学习复盘 YYYY-MM-DD」，正文带「复盘/学习/面试题」这类自然问法词（标题不进检索索引，检索词必须在正文里）。
- **「回顾昨天」变体**：目标是昨天时，先读昨天的复盘文件，额外加第 5 节「你还记得吗」——出 1~2 道复习题考昨天学的核心概念，然后给答案。

## 常见错误

- 把 git 提交列表复述一遍当「今天学了啥」——要提炼成「学会了什么」。
- 题目与当天内容脱节——题目必须能追溯到当天的具体代码/笔记。
- 只写文件不进知识库——以后问「上周学了啥」检索不到。
- 只出概念题——实现讲解题才是手写仓库的面试优势。
- 「回顾昨天」忘了读昨天的复盘文件直接出题——复习题要锚定昨天实际学过的东西。
- 复盘更新完忘了重推微信——手机上停在旧版，改完必须再跑一次推送。
