# 模块 07 · 记忆——给 Agent 装上跨会话的硬盘

> 写法提醒：同 06——自己的话、数字说话、每节先自问自答。这份文档同时是 A/B 实验报告的底稿。

## 0. 问题：会话结束了，ledger 也死了

- 和模块 06 的衔接：窗口/截断/压缩全是会话内的，记忆 = 上下文的二级存储（RAM → 硬盘）
- 四层记忆框架（认知科学 → agent 工程的映射；情景/语义二分出自 Tulving 1972，MemGPT 的「分级记忆 + 自主分页」就是这套：working = 主上下文，其余 = 外存，agent 自己调工具换页）：

| 层 | 中文名 | 存什么 | 我的系统里在哪 | 真实例子 |
|---|---|---|---|---|
| working | 工作记忆 | 当前正在处理的信息，容量极小、用完即弃 | 上下文窗口本身（模块 06 的 view） | 这轮对话里「全家 5 口人买伞」的算式——会话结束即蒸发 |
| episodic | 情景记忆 | 带时间地点的「经历」：何时发生过什么 | 没有独立通道——ledger 是原始情景，B 抽取后只剩事实，事件本身被丢掉 | 「10-13 那次会话里聊了童年在罗台村小河摸鱼」——记的是那次经历，不是结论 |
| semantic | 语义记忆 | 脱离情景的事实与知识：「是什么」 | memories/*.md 事实库（本模块的主体就是它） | 「赵德升 1994 年生，妻子李露露小一岁」——不记得哪次会话说的，也不需要 |
| procedural | 程序记忆 | 「怎么做」：流程、规范、技能 | 提示词与工具 description（常驻，不进记忆库） | 「写记忆时间要绝对化、摘要 ≤30 字」——WRITE_TOOL_DESCRIPTION 就是 procedural |

## 1. 文件型记忆（第一通道）

- 布局：MEMORY.md 索引（一行一条）+ memories/*.md（一事实一文件）；为什么索引常驻、正文按需读
- **渐进式披露的决策规则**：披露防的是「单条大」，检索防的是「数量多」——search 已经筛过「多」，top-k 是最相关的内容，单条不大就给全文（我的 search_memory 返回全文的理由）
- 写入策略 A：模型自主决定记什么——description 怎么写（判断标准先行，例子只做示意）
- 治理三件：去重（内容相同跳过）、覆盖（审计日志 + `flag:'a'`）、更新路径（「我改主意了」）

## 2. 检索型记忆（第二通道）

- 手写向量库：embed + cosine + top-k + vectors.json 持久化（约 50 行，pgvector/Milvus 本质就是这三件事 + 近似索引）
- 双通道分工：索引精确点名 vs 语义模糊检索；read_memory vs search_memory 不打架
- 探针数据（纯向量初测）：语义查询 / 实体查询的分数差异——「媳妇叫什么」0.408 vs 0.407 的掷硬币
- 结论：纯向量在实体查询上排序是浆糊 → BM25 混合检索的立项理由
- **BM25 混合检索落地**（bigram 分词 + Okapi BM25 + RRF 融合；16 条语料，纯向量列取自同跑的通道日志，干净对照）：

| 探针 | 纯向量 top1 | 混合后 top1 | 判定 |
|---|---|---|---|
| 李露露 | birth-years 0.603 | birth-years（rrf 0.033，两通道双冠军） | ✓ 共识加固 |
| 柳泉小学 | primary-school-journey 0.626 | primary-school-journey（0.033，第 2 名 0.016） | ✓ 领先幅度翻倍 |
| 999皮炎平治什么的 | eczema-history 0.680 | eczema-history（0.033） | ✓ |
| 我睡眠怎么样 | color-vision-weakness 0.473（gold 第 6） | **sleep-habits（0.032）** | ✓✓ RRF 教科书案例：单通道冠军零共识，输给双通道中等生（1/66+1/61=0.0315 > 1/61=0.0164）；「睡眠」是 BM25 从正文捞到的（摘要里只有「熬夜」） |
| 我小时候在河边干嘛 | childhood-river-memory 0.518 | childhood-river-memory（0.016，BM25 零分自动出局，退化回纯向量） | ✓ 未拉坏 |
| 媳妇叫什么 | family-diet-preferences 0.466（gold 第 6） | family-diet-preferences（BM25 全零，原样） | ✗ 两路全瞎：媳妇≠妻子（字面），话题相似≠答案（语义）→ rerank / 查询改写的立项理由 |

- 机制要点：中文 BM25 的命门是分词（bigram 零依赖解）；RRF 只用排名不用分值（cosine 窄带 vs BM25 无上界，量纲免疫）；零分文档在源头过滤（全零通道自动闭嘴，语义主场不被污染）

A 的短板——不是「忘了记录」，你的数据里它一个都没忘
4 个显式事实 A 全捕了（4/4）。「忘」是你担心的方向，但实测暴露的是另外两个问题：

噪音：A 的摘要里编造了对话没有的建议（疖肿那条的「需留意血糖」）——写和任务混在一起时，质量控制最弱
行为全靠 description 工程：判断标准、「如：」降级、例子枚举化……这次改了三轮才到位——A 的可靠性是提示词工程堆出来的
「忘」在顺带事实上确实是风险（模型注意力在任务上，「值不值得记」的判断和做任务在竞争）——但你的测试集全是显式披露，这行恰恰没测。要么补实验，要么结论里写成假设，不能当成已证明的缺点。

B——「费 token」对，「上下文超预算」说反了
B 的抽取是会话结束后的独立调用、独立上下文——从头到尾不进对话预算，你那个 6000 token 的 budget 它一个都不占。这点恰恰是 B 的设计优点。

B 的真实成本结构是固定税：纯问答、没东西可记，也照付 ~1.4k token 的抽取调用——按会话收费，不按记忆量收费。你 5 个问答 case 白交了 5 笔。

唯一沾边的担心：抽取调用的输入 = 整个 ledger 的 JSON，会话越长这笔越大（长会话抽取成本线性涨）——但这是抽取调用自己的成本，不是对话预算的压力。

AB——「token 变多」跟数据矛盾
实测 AB 16400 < B 17000。AB 不是「更多」，是「跟 B 打平的最贵一档」。单次跑这点差异就是噪声，诚实的写法是：AB ≈ B > A，后两者比 A 贵 ~50%。

AB 的真实卖点是机制互补：A 管即时性（事实当轮落盘，同一会话的后半段就能读——B 要等会话结束）、B 管完整性（专门一遍看全量）。代价是双重税 + 归因变难（哪条记忆谁写的，得翻审计日志）。

比逐条优缺点更值钱的一句话
选写策略 = 选计费模式：A 按需付费（不写不花钱），B 包月（每会话固定税），AB 双份。而噪音控制三种策略都做不到——都得靠写入管线的代码约束（字数、查重、审计），不能靠模型自觉。

- 我的结论：
- 策略A在系统提示词中提示记录记忆，容易和当前执行的任务抢注意力，有杂音，优点是省token，容易忽略掉会话中夹杂的事实。
- 策略B会话结束后，分析是否有要写入的记忆，就是费token，每次会话结束后，不管有没有要记录的事都会调用一次模型分析，不容易漏掉记忆。
- 策略AB提示词中加提示 & 会话结束后模型检查是否有要写入的记忆。token消耗和B差不多，最不容易漏掉记忆。

## 4. 记忆治理（进阶）

- 去重的根本解法：**代码侧向量查重**（写入前查 top-1，≥阈值走更新路径）——不能把一致性寄托在模型自觉上
- 阈值校准实验（同义对 / 无关对两簇的分数沟，MERGE_THRESHOLD = 0.80 落在实测沟里）：

| 场景 | 正文相似度 | 判定 |
|---|---|---|
| 同事实·分号连句 | 0.947 | 合并 ✓ |
| 同事实·bullet 列表 | 0.815 | 合并 ✓（阈值 0.85 时漏，已修） |
| 部分重叠（教育碎片） | 0.70~0.73 | 灰区，不并（mem0 的立项论据） |
| 相邻主题新事实 | ~0.59 | 新建 ✓ |
| 完全无关 | ~0.51 | 新建 ✓ |
- 升级方向（了解）：mem0 的 ADD/UPDATE/DELETE 决策 + 信息合并

## 5. 一句话总结（必填，用你自己的话）
记忆 = 给上下文装硬盘：写入端选计费模式（A 按需 / B 包月 / AB 双份），检索端两条腿走路（向量管语义、BM25 管实体、RRF 融合排名），治理端用代码查重 + 并集合并守住事实不被搅浑。
