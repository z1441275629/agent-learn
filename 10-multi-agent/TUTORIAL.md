# 模块 10 · 多 Agent——上下文隔离与并行的兑换率

> 写法提醒：同 06~09——自己的话、数字说话、每节先自问自答。
> 本模块的特殊性：**每一节都在为「值不值」记账**——多 agent 的收益（隔离+并行）和代价（token ×N）必须成对出现，光把模式写出来不算完成。

## 0. 定位：多 Agent 买的是什么

- 本质收益 = **上下文隔离 + 并行**（不是「更聪明」）：子 agent 在干净窗口里干活、只回传结论，主管的窗口不被过程污染
- 代价：token 成本 ×N 以上（Anthropic 研究系统的真实数据：约 15×）
- 决策清单（本节产出）：什么时候单 agent + 工具就够？——从任务可拆性、上下文污染程度、并行度、预算四个轴给自己的判断规则
- 资产复用地图：09 的 createAgent（天生干净上下文）、agentLoop、dispatch 咽喉（权限/hook 白送）、persist（子 agent 会话隔离落盘）——**模块 10 不新建底座，搭在 09 肩膀上**

## 1. 底座：spawn 原语

- `spawn(task, opts) → { conclusion, tokens }`：起一个子 agent、给它任务书、拿回结论——五种编排模式的共同原子
- 关键设计：传进子 agent 的上下文边界（任务书 + 必要交接物，**不是整本账**）；失败传播（子 agent 死了/超时了，主管收到什么）
- 引导问题：子 agent 回传「结论」还是「过程」？谁决定？（提示：主管窗口的洁净度就是这个决定的直接后果）

## 2. 模式一：supervisor（主管分派）

- **实现结构：派单 = 工具调用**。主管是一个普通 agent，手里唯一的工具是 `dispatch_task`，其 impl 就是 spawn——09 的循环、权限、hooks、审计原样复用，一行没重写。与 08 planner 的血缘在此分岔：planner 开工前一次出整张图（「先知」），supervisor 每收一份结论再决定下一单（「走一步看一步」）——agentLoop 在工具层 ReAct，supervisor 在任务层 ReAct，**同构，不同层**
- **上下文隔离的活证据（失控探针实测）**：全系统 prompt 106,666 tokens 里，主管自己只占 13,749——五个子 agent 合计 92,917 token 的过程全部关在各自窗口里，主管 ledger 只落截断过的结论（spawn 截断 + 工具 `maxResultTokens: 600` 双闸）。§0「窗口不被污染」不是修辞，是返回类型
- **两道防线的次序（失控探针的正主）**：「全面调研主流前端框架」任务下，软防线（提示词锚「1~3 单足够」）没拦住——主管打满 5 单；硬防线（MAX_DISPATCHES=5 熔断）封顶，第 6 单被拒返回 `{error: '派单预算耗尽，请基于已有结论直接作答'}`——**主管读懂了、收口了、三份有效回传如实标注缺失、不编造**。结论：提示词约束是行为引导，预算是物理封顶；熔断的 error 文案要让被拒的 agent 看得懂出路（09「拒绝要大声+给理由」在任务层的复用）
- **熔断计数器的坑（实测出→修）**：初版 `dispatchCount` 只有声明、比较、归零三处——**没有自增**，熔断永远 `0 >= 5` 不触发（防线写好了没接电，和 §5「判了 !lastMsg 没 return」同族）。修法之外还有个设计位：记尝试（spawn 前自增）还是记成功（后自增）——**记尝试**：失败的派单也烧钱（网络来回、半程执行），预算的意义是给一切消耗封顶，包括失败循环
- **平方账（本节最贵的一课）**：跑满步数的子 agent prompt 32,271/32,231，早收口的两单只有 9,465/9,798——无 prompt caching 下每步重发全部历史，**token 是步数的平方级**。推论：多派一个「小而专注」的子 agent，比让一个子 agent 多跑几步便宜——拆分粒度直接影响成本曲线
- **主管人设四件套**（写「管别的 agent」的提示词）：角色认知（带具体反例：不查资料/不算数/不写长文）、派单纪律（从子 agent 视角讲隔离 + 指代反例「别写『查刚才那个』」）、停止契约（数字锚比「够用就停」管用）、输出契约（标注结论来源）
- **跨模块回响（顺手记进 09 §7）**：子 agent 报「联网核验失败（沙箱拦 curl）」，但另两单拿到了 npm registry 实测版本号——`npm view` 不含路径字面量放行且自己联网，`curl https://x` 撞上 `s:/` 被拦。**「禁网」是路径正则的副产品，且不一致**——比全拦更危险的是给人已设防的错觉
- 墙钟预告：五单互相独立却串行跑了 ~20 分钟（最长单 418s）——§4 fan-out/并行的动机就在这张时间线里

## 3. 模式二：pipeline（流水线）

- A 的产出是 B 的输入，线性传递；血缘：08 planner 的 dependsOn 步间转交就是它
- 引导问题：段与段的「接口契约」怎么定？上游产出不合格，下游是硬吃还是打回？

## 4. 模式三：parallel fan-out/fan-in（并行扇出汇总）

- **并行的全部语法 = map 出 N 个 promise 一起 await**（Promise.all）；血缘：08 的无依赖子任务并发 → 任务层，Anthropic orchestrator-worker 的 worker 扇出。**省的是墙钟不是 token**——账单分文不少，只有耗时列讲真话（实测两发：112.8s vs 串行 132.1s 省 19.2s；51.1s vs 72.5s 省 21.4s）
- **省多少 = fan-out 段占全程的比例**（两发互为对照）：fan-in 慢发（思考模式归纳 ~95s）稀释收益只省 19s、fan-in 快发（~39s）占比升到 ~23% 就省出 21.4s——fan-in 恒定串行省不动它，样本越多越慢，fan-out 占比越大省得越多
- **超时弃子三件套（spawnWithDeadline）**：09 withTimeout 的任务层重写——race 观察、不取消（弃子只是「不再等」，钱照烧）、`.finally` 清计时器、**迟到补账**（真发落地即 charge）。live 证据：弃子后 0.8s 迟到者落地，日志 + 补账双出，真账 4/4 数字自洽（5250 − 1178×3 = 1716 恰是 fan-in 的 prompt——迟到的 1178 在账上）
- **弃子 ≠ 异常（本节最大设计课）**：09 版超时 reject（钩子失败=异常），这版超时 **resolve 合成样本**（弃子=带缺席信息继续走的正常流程）——因为上游是 Promise.all：**race 里允许输的一方，输的动作就不能是 reject，一发 reject 整团崩**（弃子变团灭，评审第一问题）
- **弃子探针三验收全过**：合成样本进交接物带「无效（超时弃子）」标注、迟到日志+补账、fan-in 备注头一条申报「样本 2 超时无效未采用」——**缺席是归纳的信息，不是垃圾**（占位文字没被当内容，空手 ≠ 消息丢失三连收官）
- **计划外的宝藏——真分歧**：样本1 称「上下文超限会被截断或报错」、样本3 称「最开头消息会被挤掉」——这不是幻觉，是**真实现差异**（硬报错/硬截断/滑动窗口挤头部，06 模块三条路线）。**多样本对有争议的技术点确实会分叉，分歧标注让分叉可见**——fan-out 的价值第一次超出「保险」
- fan-in 任务书三段式（收到什么/怎么合/交付什么形状）+ 四归纳规则：去重（重合部分合并为最完整表述）、选优（标准写具体：对新手最友好）、**分歧标注（点名样本、不许悄悄选边或和稀泥）**、缺席处理（无效样本的占位文字不许提取观点，回答开头申报缺席数）
- 隔离的对称性证据：三发同题样本 prompt 完全相同（1178）——干净窗口的造价可预测；completion 方差 4 倍（769 vs 185）——**completion 不可当产出的稳定代理**（§9 账本口径预警）
- 口径分叉记账：token 侧抓住迟到者（落地即记）、墙钟侧的「串行和」用弃子时刻的 12s 不算迟到者继续烧的时间——两个口径各自合理，但读账时要知道你读的是哪个
- 评审四问题全录：① reject 方向反了（团灭路径）② catch(console.log) 把异常吞成 undefined 进管线（兜错要兜成失败样本，不是「没有样本」）③ charge 收了从未调用（三件套装了一件半——没接的参数=没写的功能）④ 错误日志整份任务书刷屏

## 5. 模式四：handoff（交接）

- **方向差（本模块的分水岭）**：前四种是 spawn 系——结论反向流回主管、主管常驻；handoff 是控制权正向流走、主管离场——用户后续的话直接对 B 说，A 的窗口从此是历史。对照实物：ZCode/Claude Code 的 subagent 转交。**没有新原语没有新循环**，09 agentLoop 原样跑，变的只是「下一句话进谁的窗口」
- **账单的可见信号**：「N 个 agent 在场」——剧本 1（天气自答）1 个、剧本 2（转交）2 个，handoff 发生与否看账单就知道
- **移交包三字段实测（剧本 2）**：reason（给 B 的第一句话：「超出职责范围，请接手专业审查」）/ originalRequest（一字不改）/ conclusion **超纲发挥**——A 转交前传了「用户尚未贴代码，需先索取」这个关键观察，B 冷启动第一动作直接据此向用户索取——**conclusion 字段不是走过场，A 的那一眼扫描决定 B 的第一步**
- **B 的三方验证**：自报家门一字不差复述了 systemExtra 人设（「擅长并发安全、类型系统与常见缺陷模式」）——system 位生效铁证；「先结论再按严重度逐条」契约原样执行；产出零 A 过程叙述——红线干净，移交包确实是最小集合
- **「你是谁」与「发生了什么」分位**：人设走 system 位（systemExtra），移交包渲染走 user 位（任务书）——B 之所以值得接权靠被专门塑造的身份，混了位置就成了「接盘侠」（评审出的真缺口：初版没给 B 人设）
- **皮球探针反打——本节最值的一课**：把白名单删到只剩「查天气」，算数题 A 照样自己答（还用 run_shell 验证了 9.9>9.11）——**能力白名单是软锚不是硬闸**：删的是提示词里的四个字，模型的算数能力没被删掉；白名单与「能做的自己做」元规则冲突时，真实能力先验赢。与 §2 软硬防线完全同构：提示词约束是行为引导，硬闸在 harness 层——**控制工具面**（A 挂着 run_shell 就永远「能算数」）；实物 Claude Code 的 triage 是 harness 层代码路由，不靠 agent 自觉
- 评审三问题：① 模板字符串缩进污染**第三次复发**（§3 教过、修过、又犯——跨行必 join('\n') 要长进肌肉）② 指代失配「转交给B」——A 的世界里只有 hand_off 工具没有 B（§2「查刚才那个」换马甲）③ B 无专家人设
- 接口契约以实物为准的正面教材：骨架的 onToolCall 我写成 `(name, args)`，09 实际签名是单对象 `{name, arguments, result}` 且 arguments 是原始 JSON 串——**用户当场逮住并修正**（顺手 JSON.parse），scaffold 的错被学习者的 09 真签名治了
- 顺带 live 两笔：run_shell 权限闸在 demo 里实战（auto 模式唯独它走确认，按 y 放行——09 设计在模块 10 被顺手验收）；hand_off 工具返回只给 A 告别语、移交包从 args 走不占 A 窗口（maxResultTokens: 200 的用意）

## 6. 模式五：generator-critic（生成-评审）

- **组装赛定位**：无新原语——§3 的打回循环 + §1 的隔离 + §2 的熔断。与门检的分工兑现了 §3 那句预言：**门检判形状**（check 函数、零成本、判不了好坏），**critic 判质量**（spawn 一发、真金白银、能说「这句没依据」）——判据里混进质量判断两头不占，分开各满血。被拒稿从「带标注放行」变「修订指令喂回重写」——**批评被消费，不是被记录**
- **首锚纪律（子串陷阱）**：输出契约锚定首行 `PASS`/`FAIL` 英文短锚——中文「检查不通过」包含「通过」，内容判 `includes('通过')` 必误判；「一行=通过」的形状判定会被单行意见击穿（critic 把意见写成一行 → 误判通过 → 坏稿放行 critic 白花钱）。**契约的字面与解析的判定必须锚同一个东西**
- **fail-closed 安全网**：解析失败（空输入/非锚首行/PASS 拖尾）不放行也不静默——合成「评审契约违约」诊断 issue。实测证明其正确与不足：正确在三连违约全被逮住诚实降级；不足在违约 issue 喂给 generator 重写是**缘木求鱼**（违约的是 critic 不是 generator，两发重写白烧——严格设计应重跑 critic，根因修掉后违约罕见，安全网留作兜底）
- **判据需要什么，交接物就要给什么（本节最贵一课，修前实测）**：事实性条款要求对照素材，handoff 只给稿件——critic 判不了就**自己去找**：正文里写 `type note.md`、裸吐 run_shell JSON。**空工具面挡住 API 层的 tool_calls，挡不住 agentic 先验往正文里漏**；任务书缺陷以工具幻觉的形式显形。修法：素材进 handoff + 任务书明说「你没有工具，一切已在交接物里」——修前熔断 completion 11724 → 修后干净通过 7557，**同一探针修前后两副面孔，差额就是设计缺陷的价格**
- **Goodhart 的 agent 现场版（熔断探针实录）**：矛盾标准（≤100 且 ≥150）物理不可满足时，generator 的目标函数从「写好周报」滑向「凑过评审」——拿字数统计（91/96/120/100）冒充「具体数字」充数，被 critic 拆穿：「字数统计元信息而非内容数字，且该括注按针对性条款应删除，不计入」。**指标成为目标后就不再是好指标；critic 的存在意义就是把凑数拆穿**——两个 agent 的攻防才是本节的深意
- **逐词级核对是 critic 的天花板**：「『杜绝半截文件』较素材『防半截文件』语义加重」——防→杜绝是无依据强化。门检查一百遍也到不了这个精度，这是花真钱买的能力
- **元认知时刻**：熔断交付的未解决项第 3 条——critic 指出判据本身矛盾：「『≤100 且 ≥150』为自相矛盾条件，任何稿件均无法同时满足｜请上游澄清（疑为 100–150 字笔误）」。不无限挣扎，把诊断交回上游——**熔断交付不是甩锅，是把问题说清楚**
- **严判探针的正路径**：数字性标准（≥2 处具体数字）打回后，generator 从素材里**数**出数字（1 项改造/2 种行为不一致/2 项计划）——事实性与数字性两条标准互为约束时，「编数字」的路被夹死，只能走「数素材」
- **两标准互搏的彩蛋**：generator 交稿自带合规声明（「全文 103 字、含 3 处可核对数字」）——把 checklist 内化成自检；下一轮被 critic 判「写给上游的元信息不服务读者」打回——**合规声明本身成了违规项**，攻防又上一层
- **轮次账**：评审数=修订数+1（最后一轮评审必要——得知道最后的稿过没过），MAX_REVISIONS=2 → 最多 3 critic+2 重写=5 发，每轮双份成本；thinking:false 未生效（completion 24000 反升，GLM coding 端点不认 `thinking:{type:'disabled'}`）——端点思考控制待查参数名，慢的主因仍是思考 token（墙钟≈completion÷输出速度，实测 ~56 token/s）
- 评审四问题全录：①「一行=通过」形状判定（单行意见击穿+子串陷阱）②空输入静默空转（打回但零修订指令，generator 盲改）③ slice(1) 吞首行 ④ 检查项黏一行没编号、反面警告照抄骨架注释（那句是给写标准的人看的）、契约字面没钉死（「一行结论通过」到底写什么字？）

## 7. 组合系统：研究员 → 写手 → 审校

- pipeline（研究→写作）× generator-critic（写作⇄审校打回）的组合拳，产出周报或调研报告
- 工具层复用旧资产：研究员配 02 RAG / 07 记忆检索
- 失败传播全链路：研究员空手而归时，写手该收到什么？（空手 ≠ 消息丢失）
