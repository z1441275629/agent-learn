## 核心内容总结
这篇文章是 Anthropic 对其 Claude “Research” 功能背后多智能体系统的完整工程复盘。核心结论是：在开放式研究任务上，多智能体架构显著优于单智能体。具体数据：以 Claude Opus 4 为主智能体、Claude Sonnet 4 为子智能体的系统，在内部研究评估中比单智能体 Claude Opus 4 性能高出 90.2%。

### 关键发现与数据：

- Token 用量是性能的最大解释因子。在 BrowseComp 评估中，仅 token 消耗量一项就解释了 80% 的性能方差。

- 速度提升：双层并行（主智能体并行启动 3–5 个子智能体，每个子智能体并行调用 3 个以上工具）使复杂查询的研究时间缩短高达 90%。

- 代价高昂：多智能体系统消耗的 token 约为普通聊天交互的 15 倍，因此只适用于任务价值足够高、且可高度并行化的场景。

### 核心思想
1. 用“架构”突破单模型的上下文与注意力瓶颈。
单模型的 200K 上下文窗口在复杂研究中很快会被塞满，且长上下文中模型对中间信息的注意力会衰减。多智能体的解法是关注点分离：每个子智能体拥有独立的干净上下文，只专注一小块任务，将精炼后的结果回传主智能体。搜索的本质是压缩，子智能体就是并行运转的“压缩器”。

2. 模仿人类集体智慧，而非单个天才。
Anthropic 明确类比：人类过去十万年个体智力没有指数级飞跃，但集体协作让社会能力指数级增长。多智能体系统是在架构层面“复刻”这种集体智慧——智能达到某个阈值后，扩展能力的关键不再是单个模型更强，而是更多模型协同。

3. 提示词工程是调节多智能体行为的核心杠杆。
早期系统曾为简单查询生成 50 个子智能体、无休止搜索不存在的来源。解决方案不是改代码，而是通过提示词嵌入工作量缩放规则：简单事实查询只需 1 个 agent、3–10 次工具调用；复杂研究才动用 10 个以上子智能体。此外，团队还创建了“工具测试智能体”，让模型自己试用有缺陷的 MCP 工具并重写工具描述，使后续任务完成时间缩短 40%。

4. 评估必须“结果导向 + 小样本快速迭代”。
不要等几百条测试用例就绪才开始评估。Anthropic 从约 20 条真实查询起步，用 LLM-as-judge 对事实准确性、引用质量、完整性、来源质量打分。但人工测试不可替代：人类测试者发现早期 agent 会优先选择 SEO 内容农场而非权威来源，这一偏差仅靠自动化评估难以察觉。

5. 生产化需要为“有状态、非确定性”的 agent 重新设计工程保障。
agent 长时间运行、状态持久、错误会级联放大。解决方案包括：从断点恢复而非重启、全链路生产追踪（不监控对话内容以保隐私）、彩虹部署（新旧版本并行渐进切换，避免中断进行中的长任务）。
