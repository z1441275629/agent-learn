# 学习复盘

用户的每日学习复盘仪式：把当天（或指定日期）学到的东西总结成可留档、可复习、可面试自测的 markdown，**双落盘**（reviews/ 文件 + 知识库笔记）。核心是**考自己**，不是复述。

## 步骤

1. **确定目标日期**：先调 `get_time`。目标 = 今天；用户说「昨天/前天」则目标日期 = 对应日期（昨天 = 今天减一天）。
2. **采集素材**（能并行的并行调用）：
   - `git_log`（since = 目标日期、until = 目标日期的次日、max ≥ 50，如目标 2026-11-03 → since:"2026-11-03 00:00"、until:"2026-11-04 00:00"）拿**当天**提交——复盘的权威来源。返回每行是「提交号 日期 消息」，只保留日期 == 目标日期的行（since 是下界，不配 until 会混入其后几天的提交，提交密集的日尤其明显）。提炼成「学会了什么」
   - `search_kb` 查「工作日志」「学习日志」「复盘」等词，看有没有当天相关笔记
   - 目标日期的旧复盘（`reviews/<日期>.md`）用 `read_file` 读，避免重复出同样的题
3. **写文件** `reviews/<目标日期>.md`（write_file；若文件已存在先 read_file 旧文，在原文件上更新，保留历史不覆盖）。内容四节：
   - `## 1. 今天学了啥`：3~6 条要点，提炼「学会了什么」，不是复述提交
   - `## 2. 核心知识讲解`：今天最核心的 1~2 个概念讲透（是什么/为什么/怎么用/和什么相关），背下来就能面试用
   - `## 3. 面试题`：3~5 题，**两类都要**——概念/原理题 + 实现讲解题（针对当天真实写下的代码/设计；拿不准怎么出时 read_file 读 `personal-agent/skills/learning-review/questions-guide.md`）
   - `## 4. 参考答案`：每题要点式答案，面试能直接说出口的颗粒度
4. **镜像进知识库**：`add_note` 存一份，title「学习复盘 <目标日期>」，text 是全文，**正文里带上「复盘/学习/面试题」这类自然问法词**（标题不进检索索引，检索词必须在正文里）。
5. **「回顾昨天」变体**：目标 = 昨天时，额外加第 5 节 `## 5. 你还记得吗`——1~2 道复习题考昨天复盘里的核心概念，然后给答案。

## 规则

- 题目必须锚定当天实际内容（当天提交/当天笔记），不许用通用题凑数
- 两类题都要：概念/原理 + 实现讲解，缺一类算没完成
- 答案是面试颗粒度：要点式，能直接说出口
- 双落盘都要做：write_file 进 reviews/ + add_note 进知识库
- 目标是昨天但读不到旧复盘文件：明说没有旧文，照常出前四节
- 目标日期确实没有任何记录（git_log 空 / search_kb 空 / 旧复盘不存在）：明说没有记录、不编造，把邻近可参考的记录列出来（目标日前/后几天的提交或笔记），问用户要不要补记当天内容
