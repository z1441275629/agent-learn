# 面试题写作指南（学习复盘技能的支撑参考）

复盘第 3 节「面试题」是最难的部分，这里给套路。拿不准怎么出题时读这份文件。

## 两类题都要

1. **概念/原理题**：考「为什么这样设计」。例：MCP 错误分层为什么协议错和执行错要分开？
2. **实现讲解题**：考「你真实写下的代码」。例：讲讲你的 pendingCalls 为什么要排干再退？——针对当天提交里的具体代码/设计。**这是手写仓库的面试优势**：别人只能背文档，你能讲自己造的车。

## 出题原则

- 题目锚定当天的提交/笔记，不许用通用题凑数（「什么是 RAG」这种任何一天都能用的题 = 不合格）
- 概念题 1 题起步、实现讲解题 1 题起步，共 3~5 题
- 实现讲解题要能追溯到具体文件/函数/设计决策，答案里给原因（为什么这么写，不这么写会怎样）

## 示例

**概念/原理题**：技能发现与执行为什么要分离？系统提示里只放索引、正文加载时才进上下文。
要点：索引小 → 系统提示省 token；描述只写触发条件防模型走捷径跳过正文；加载才看全文保持上下文干净。

**实现讲解题**：讲讲你的 core/skills.ts 为什么让技能名必须等于文件/目录名，重名直接抛错。
要点：名字要拼进路径 → 不校验会留路径穿越面；重名抛错不静默吞 → 索引和加载永远一致，坏技能在索引期暴露而不是让模型幻觉出内容。
