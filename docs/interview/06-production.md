# 06 · 生产工程化

> 覆盖：成本结构 / 延迟优化 / SSE 重连 / 并发限流 / 缓存 / 超时取消 / 可观测。从 demo 到生产，差的就是这一章。

### Q1. LLM 应用的成本结构是什么样的？钱都烧在哪？【必背★】

**背诵版**：成本 = token 单价 × 用量，但**结构比单价重要**：① ReAct 循环**每轮重发全部历史**（system+历史+工具结果），多轮任务的成本是平方级累加——这是 agent 最大的成本黑洞，优化首选用源头截断工具结果+压缩历史；② **输入通常远大于输出**（长 prompt 短答案的任务输入占大头），长上下文任务要盯输入单价；③ 编排层自身有隐藏成本（路由/规划/审校每次都是调用），**全链路 usage 记账**（每个环节的 token 都记）才能看见隐形开销；④ 模型分档（简单任务走轻量档）是最大的单点杠杆。**没有记账就没有成本工程**——先让每个环节的消耗可见。

**追问**：Q：怎么快速判断一个任务贵不贵？→ 估算「平均轮次 × 平均上下文长度 × 单价」，重点看轮次和上下文长度这两个放大器。Q：记账记什么粒度？→ 节点级（路由/规划/执行/审校分开），能归因到环节才能优化。

### Q2. 用户嫌慢，你从哪下手优化延迟？【必背★】

**背诵版**：先测后优，延迟拆解：**TTFT（首字时间）+ 出字速度 + 轮次数**。手段按性价比排序：① **流式输出**——TTFT 从几十秒降到一两秒，体感提升最大的一刀；② **模型分档**——简单节点换轻量模型（TTFT 和出字速度都改善）；③ **并行化**——独立工具调用并发、独立子任务并行；④ **prompt 瘦身**——上下文短了预填充快（还省钱）；⑤ **prefix cache**——稳定前缀（system+工具定义）命中缓存跳过预填充；⑥ 减轮次——工具结果截断让模型少消化。**体感层面还有一招：进度反馈**（「正在查询…」的自定义事件），等待有反馈就不焦躁。

**追问**：Q：TTFT 和总时长矛盾吗？→ 有时（推理型模型思考久但一次答对、总时长反短）——按场景选平衡点。Q：流式对服务端有什么要求？→ 边生成边转发（别攒完再发）、断开即 abort（别白烧）。

### Q3. SSE 断线重连怎么做才是对的？【必背★】

**背诵版**：核心是**服务端有状态、重连有补发**：① 服务端把关键事件流持久化（或可重建），连接只是视图——**连接断了状态不能丢**；② 重连时补发「当前挂起状态」而不是重放全量历史流（用户要的是「现在进行到哪」，不是从头再看一遍）；③ 自定义帧协议（event 类型+data 载荷）区分增量内容与状态事件；④ 心跳/超时检测死连接（半死连接最坑：客户端没了服务端还在写）。原生 EventSource 自带重连，但**自定义帧协议+fetch 手撕 SSE 时重连语义要自己实现**——这是高频偷懒翻车点。配合客户端 abort：用户关页即取消上游调用，别烧无效 token。

**追问**：Q：重连补发和重放怎么选？→ 幂等的状态事件可以重放，token 流不能（会重复渲染）——所以增量帧带序号，状态帧可重发。Q：多实例部署怎么办？→ 状态外置（redis/消息总线）或会话粘滞，不然重连打到另一台机器拿不到状态。

### Q4. 上游限流（RPM/TPM）怎么应对？你的并发怎么管？【进阶】

**背诵版**：分层处理：① **客户端并发控制**——队列+上限（如 p-queue），把对外并发压在上游限额内，别把 429 打成雪崩；② **限流响应处理**——429 读 Retry-After，指数退避+抖动重试，尊重服务端节奏；③ **错峰与削峰**——批量任务排队跑，交互任务优先；④ **多 key/多供应商容灾**——限额耗尽切备用档（配合模型路由）。反向也要管自己：**工具并发、子 agent 并发同样要有闸**（墙钟可控、资源不穿），无上限的 Promise.all 是事故预定。

**追问**：Q：TPM 和 RPM 哪个先卡住？→ 长上下文任务通常 TPM 先到，监控两个维度分别预警。

### Q5. token 成本治理，你实际做过什么？【必背★】

**背诵版**：四板斧：① **全链路 usage 记账**——路由/规划/执行/审校每个环节的 token 都落盘，月末能按环节归因（不记账的优化都是感觉）；② **源头截断**——工具结果限长（网页几千字截断+标注），这是 ReAct 成本黑洞的第一刀；③ **历史压缩**——旧轮摘要+增量原文（第 5 章 Q4），长会话成本从平方级压回线性；④ **模型路由**——四档（主/小/备用/视觉）按任务分档，简单任务（路由判定/摘要/格式化）走小档。效果口径注意：**讲机制和前后参数，没有系统性基准就不编百分比**。

**追问**：Q：哪个动作收益最大？→ 通常「截断工具结果」——一次改动能砍掉最大头的低密度 token。Q：怎么防优化反弹？→ 把 usage 记账做成常开监控，成本异动报警。

### Q6. LLM 应用能做什么缓存？【进阶】

**背诵版**：三层：① **prefix/prompt cache（API 层）**——system+工具定义等稳定前缀命中厂商缓存，跳过预填充算力（省钱省 TTFT）；工程纪律是**稳定前缀放最前、易变内容放最后**，别让动态内容打散缓存。② **精确结果缓存**——幂等请求（同样输入的判定/抽取）按内容键缓存复用；注意带时间性的答案不能缓。③ **语义缓存**——相似 query 命中历史答案，风险是「相似≠同义」，错命中直接答非所问——**生产上慎用，除非场景容错高**。缓存共同纪律：失效策略想清楚（知识变了缓存要不要跟着变）。

**追问**：Q：prefix cache 怎么确认命中？→ 部分 API 返回 cached_tokens 用量字段，对账看命中率。

### Q7. 超时和取消怎么设计？AbortController 用对了吗？【必背★】

**背诵版**：三条纪律：① **取消要贯通**——用户关页/SSE 断开 → AbortController signal 一路传到上游模型调用和工具执行，不贯通就是「人走了钱还在烧」；② **abort 归因**——异常处理先查 `signal.aborted` 再归错误：**主动取消不是故障**，混在一起会污染可靠性统计、触发无意义的告警和重试；③ **半截语义**——被取消的生成物按明确规则处理（保存已生成部分并标注「未完」/丢弃），别留模糊态。超时同构：超时=自动取消+「未知态」处理（超时不等于失败，可能已执行一半，写操作超时要查询确认而不是盲目重试）。

**追问**：Q：abort 后还要记日志吗？→ 记，但打上 cancelled 标签独立统计——取消率是产品信号（用户等不及）。

### Q8. LLM 应用部署有什么特殊的坑？【进阶】

**背诵版**：① **长连接**——SSE/流式被网关缓冲（要 `X-Accel-Buffering: no` 类配置）和超时切断（网关 idle timeout 要大于生成时长）；② **无状态+外置状态**——应用水平扩，会话状态在 checkpointer/redis，SSE 重连才不受实例切换影响；③ **密钥管理**——API key 走环境变量/密管，绝不进代码库和日志；④ **冷启动**——常驻进程 vs serverless（冷启动撞上首 token 延迟，交互场景慎用 serverless）；⑤ **依赖进程**——浏览器 agent 这类带子进程的要管进程树生命周期（起、回收、孤儿检测）。部署清单里一半是「连接和进程别断」，这是流式应用的特殊性。

**追问**：Q：本地开发好的流式上了线变一次性输出？→ 九成是代理/网关缓冲，逐层排查缓冲配置。

### Q9. prompt/模型变更怎么灰度发布？【进阶】

**背诵版**：LLM 应用的「代码」一半是 prompt 和模型版本，变更管理要覆盖：① **变更即版本**——prompt 模板、模型版本、温度参数都纳入版本管理，可回滚；② **离线评测门禁**——变更先跑评测集，关键指标不回退才放量；③ **灰度分流**——按流量比例逐步切（先 5% 再全量），线上监控（成功率/成本/延迟）盯异常；④ **快速回滚**——配置化切换（环境变量级），不是改代码重新部署。**模型供应商升版不通知你也会变行为**——重要应用锁版本号，主动升级走同样门禁。

**追问**：Q：线上怎么发现「变笨了」？→ 常开的质量探针（固定任务定期跑）+ 用户负反馈率监控，不能只盯报错率。

### Q10. LLM 应用的可观测性，最小集合是什么？【必背★】

**背诵版**：三件套：① **trace**——每个请求的完整链路（每个节点/工具的输入输出摘要+耗时）贯穿一个 trace id，出错能回放整条决策链；② **usage 记账**——token 按环节/按会话/按天落盘，成本可见可归因；③ **失败分类统计**——错误不是一堆日志要按类聚合：模型侧（超时/限流/内容过滤）、解析侧（结构化输出失败）、工具侧（执行失败/被守门拒绝）、用户侧（主动取消）——**每类失败有自己的告警阈值和处置预案**。工具上 LangSmith/Langfuse 类或自建落盘都行，关键是字段设计：会话/节点/输入输出/token/耗时/结果状态。**没有可观测的 agent 系统是黑盒，黑盒没法运维也没法优化**。

**追问**：Q：trace 里记全量输入输出吗？→ 记摘要+采样全量（存储成本），排障时可按 trace id 取完整明细。Q：日志里有 PII 怎么办？→ 落盘前脱敏或本地保留策略，日志也守 PII 纪律。
