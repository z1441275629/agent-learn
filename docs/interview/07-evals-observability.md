# 07 · 评测与可观测

> 覆盖：评测集设计 / LLM-as-judge / 离线与线上 / 方差 / tracing / 零 token 测试 / 坏例回流。「你怎么知道它变好了？」——这道题答不上来，前面的工程都是感觉工程。

### Q1. 从零给一个 agent 系统建评测集，你怎么建？【必背★】

**背诵版**：① **固定任务集**：挑 20~50 个真实任务（覆盖功能面+难度梯度，含「该拒绝的任务」和「知识边界题」），输入固定、判分标准预先写死——先有标准再跑，不能跑完再解释；② **分层判分**：不只判最终答案——**过程也要判**：期望调用的工具、调用顺序、禁止调用的工具、落盘副作用（写了文件就去查文件）、答案关键词；③ **可复跑**：报告+全量明细落盘，前后两版能对比；④ **真实模型实测**：mock 测不出模型行为，评测必须打真模型。品类上再加一类：**寒暄/无关任务**（防过度触发）。评测集是活资产——线上坏例持续回流进来（见 Q8）。

**追问**：Q：20 个任务够吗？→ 起步够（比 0 强一个量级），按功能域均衡覆盖；样本量小时更要看逐任务明细而不是只看总分。Q：判分标准怎么写才不主观？→ 期望工具序列/关键词/文件断言都是客观判；开放性答案用 judge（见 Q2）。

### Q2. LLM-as-judge 怎么用才靠谱？它有什么偏差？【必背★】

**背诵版**：judge 的正确用法是**锚定比对、不做知识发挥**：给 judge「参考答案+用户答案」，指令限定为「参考答案里的要点，用户讲到什么程度」——评分是要点比对不是重新答题。防偏差四件套：① **温度 0**（判定节点锁参，否则同一输入两次评分不同，评测本身不可复现）；② **结构化评分**（分数+命中要点+遗漏要点，不只是给个数字——可审计）；③ **参考答案锚定**（防 judge 用自己的知识自由发挥）；④ **克制校准**（prompt 里明确「全中且理解对才满分，沾边给中间分」——judge 默认偏宽松）。已知系统性偏差：偏爱长答案、位置偏差（先给的答案评分高）、自我偏好（同族模型互评偏高）——校准用人工抽检。

**追问**：Q：judge 分数和人工不一致怎么办？→ 抽检对齐：拿人工标过的样本调 judge prompt，收敛后再用；不收敛的场景放弃 judge 改规则判分。Q：judge 也在烧钱，怎么省？→ 规则能判的（关键词/工具序列/文件断言）不上 judge，judge 只判开放性维度。

### Q3. 谁来评测评测本身？（judge 的校准与元评测）【进阶】

**背诵版**：三层校准：① **人工抽检**——随机抽 judge 判过的样本人工复核，算一致率，一致率掉就是 judge 漂移了（prompt 没变但模型升版会漂）；② **金标集**——人工标好分的固定样本，judge 每次变更后先跑金标集，偏差在阈值内才上线；③ **反向验证**——故意构造「应该低分」的样本（胡答/漏要点）混进去，judge 给高分说明锚定失效。元评测的成本意识：**judge 是基建，校准一次管很久，但不校准的 judge 比没有 judge 更危险**（给你虚假的质量信心）。

**追问**：Q：多 judge 投票有用吗？→ 对抗单一模型偏差有用，成本翻倍——先穷尽锚定+温度+结构化，投票是最后手段。

### Q4. 离线评测和线上监控各管什么？【必背★】

**背诵版**：**离线评测**是变更门禁：固定任务集+固定判分，回答「这个改动能不能上」——可控、可复现、但分布是模拟的（会过拟合到评测集）。**线上监控**是真实反馈：真实流量的成功率、成本、延迟、负反馈率、坏例样本，回答「上线后实际好不好」——真实但不可复现、有滞后。两者闭环：**线上坏例回流进离线评测集**（防同类回归），离线指标和线上指标定期对账（离线涨线上没涨=评测集失真）。只有离线=活在模拟器里；只有线上=拿用户当测试。

**追问**：Q：线上成功率怎么定义？→ 按任务定完成判据（用户确认/最终态达成/负反馈率），agent 的「成功」常常要业务口径。

### Q5. 评测跑一次就下结论，有什么风险？【必背★】

**背诵版**：**单次运行有方差**——LLM 输出非确定（即使温度 0 也有批推理非确定性），任务集小+单次运行=结论可能是噪声。纪律：① 重要对比跑多次（或至少关键任务多次采样），报均值±波动；② 改动效果小于波动幅度 = 没有结论，别硬讲故事；③ 样本小看**逐任务明细**：哪些任务从对变错、错变对——比总分信息量大；④ 诚实口径：评测报告标注「单次运行 v1」这类限制，被追问复跑方差时如实说。**把单次 100% 当成稳定 100% 是评测里的自欺**。

**追问**：Q：什么改动值得跑多次评测？→ 影响行为的（prompt/模型/温度）；纯重构零 token 测试覆盖的走回归就行。

### Q6. tracing 具体怎么做？字段怎么设计？【必背★】

**背诵版**：目标：**任一次执行都能回放整条决策链**。落地：① **trace id 贯穿**——一次用户请求一个 id，跨节点/跨子 agent/跨工具全部携带；② **节点级记录**——每个模型调用/工具执行的输入摘要、输出摘要、耗时、token、结果状态（成功/失败/取消/被守门拒绝）；③ **存储分层**——摘要常存（列表可查），全量明细按 trace id 可取（排障时再拉），控制成本；④ **串联业务语义**——记录「这步为什么发生」（路由判定结果/规划步骤号），不只是「发生了什么」。工具：LangSmith/Langfuse 或自建 JSON 落盘，字段设计比工具选择重要。

**追问**：Q：trace 太大怎么办？→ 输入输出截断+采样策略，关键链路（失败/高价）全量留。

### Q7. agent 的回归测试怎么做？「零 token 测试」是什么？【进阶】

**背诵版**：把**拓扑逻辑和模型行为分开测**：① **零 token 测试**——判官/模型注入 fake（返回固定结构化结果），测图的拓扑：条件边分支对不对、interrupt 挂起恢复对不对、reducer 合并对不对、抽题策略纯函数直测——**图逻辑的回归不该烧真钱**；② **mock 模型测试**——按剧本返回预设消息流（含 tool_calls 序列），测执行层（调度/回填/终止闸）不花 token；③ **真模型冒烟**——少量关键链路打真模型验证接线（协议/格式），放 CI 的手动档或低频档。三层金字塔：零 token 全量高频、mock 中频、真模型少量。**能把测试和推理解耦，agent 才有工程迭代速度**。

**追问**：Q：fake 判官怎么注入？→ 依赖注入设计（图工厂接 judge 参数），测试传 fake——顺便让判官本身可替换可评测。

### Q8. 线上坏例怎么回流成评测资产？【进阶】

**背诵版**：闭环四步：① **捕获**——负反馈按钮/失败分类日志/用户投诉里捞真实坏例（保留完整 trace）；② **最小化复现**——把坏例裁剪成最小任务（去 PII、保结构）；③ **入集**——进评测集并标注期望行为（该答对的样子），成为永久回归用例；④ **归因分类**——坏例按层归档（检索没召回/模型没遵循/工具失败/设计缺陷），同类聚集说明系统性问题不是随机噪声。**坏例是评测集最有价值的增量**——自己编的题目测的都是你想得到的，用户踩的坑才是真分布。

**追问**：Q：坏例多久回流一次？→ 定期批量（如每周）+ 重大故障即时；回流要有入集标准（可复现、已定位）。

### Q9. 评测集怎么防过拟合？【进阶】

**背诵版**：评测集变题库背下来就失效了：① **防泄漏**——评测任务/参考答案绝不进任何 prompt、few-shot、知识库（有人把测试题喂进 RAG，评测满分线上翻车）；② **多样性维护**——同类任务变换表述/参数生成变体，别让优化瞄准固定字面；③ **定期换血**——部分任务轮换更新（旧任务降级为回归用例，新任务当门禁）；④ **多指标制衡**——成功率+成本+延迟一起看，防单一指标被优化到失衡（为成功率堆轮次烧钱是常见跑偏）。**评测集的健康度=它还能不能预测线上表现**，离线线上对账（Q4）是终极检验。

**追问**：Q：发现 prompt 里混进了评测题怎么办？→ 立即清除并重跑受影响的评测结论——污染过的分数全部作废。
