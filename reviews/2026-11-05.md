## 2. 核心知识讲解

**MCP server 供给者视角**（今天的主线）：

- **是什么**：Model Context Protocol——把能力外露成标准工具，给任意 MCP 客户端用。stdio 传输 = 每条消息一行 JSON + `\n`；**stdout 只走协议消息，stderr 走日志**——调试日志绝不污染协议通道
- **生命周期**：客户端 `initialize`（带 protocolVersion）→ 服务端回显能力集 + serverInfo → 客户端发 `notifications/initialized` 通知（无需应答）；之后 `tools/list` 拿工具清单、`tools/call` 调工具
- **错误两层**（协议的核心纪律）：参数非法 / 未知工具 → JSON-RPC 错误（-32602），这是「请求本身不对」；工具执行失败 → `isError:true` 的正常结果，这是「请求对、结果坏」——模型能读到原因并调整，连接不断。区分开，客户端才能分清「我调用错」和「它运行挂了」
- **版本协商**：请求的版本支持就回显，不支持就回自己最新版（规范 SHOULD）
- **写侧安全**：MCP 协议没有确认卡语义，写工具审批交给客户端（Claude Code 对写操作逐个请求批准）——与工作台内 SSE 确认卡是同一原则的两处落地
- **双分工设计**：`browser_inspect` 在 MCP 里直接返回 image 内容块（感知交给客户端模型），工作台内则用视觉档子调用喂文字——同一能力，两种分工

## 3. 面试题

概念/原理题：

1. MCP 的错误为什么分「协议错误」和「执行错误」两层？分别怎么表示？
2. stdio 传输为什么规定 stdout 只能走协议消息、日志必须走 stderr？
3. MCP 协议没有确认卡，写侧工具的安全靠什么保证？

实现讲解题：

4. 讲讲你手写的 mcp-server 的版本协商：请求 2024-11-05 会怎样？请求 1999-01-01 会怎样？
5. `pendingCalls` 为什么要在 stdin 关闭前排干在途应答？如果不排干会怎样？
6. `pa-mcp` 全局命令为什么用 in-process import 而不是 spawn 子进程？

## 4. 参考答案

1. **协议错误** = 请求本身形状不对（未知方法 / 未知工具 / 必填缺失）→ JSON-RPC error 带 code（-32601 / -32602）。**执行错误** = 请求合法但工具运行失败（网页打不开、存储写失败）→ 正常应答里 `isError:true` + 文本原因。区分价值：客户端能分辨「我调用错了该改」vs「它运行挂了该重试 / 看原因」；执行错误以结果形式喂回模型，模型自己调整，连接不断。
2. stdout 是协议专用通道，客户端逐行读它当消息解析——混入日志会破坏封帧，一行 JSON 被日志打断客户端就崩；stderr 是标准日志通道，客户端收进自己的调试日志，互不干扰。
3. MCP 协议本身没有确认卡。写侧工具安全靠**客户端权限门**：Claude Code 对不在 allow 名单里的 MCP 工具逐个请求批准，拒绝就不执行——与工作台里 SSE 确认卡（参数原文亮给人看、批了才跑）是同一原则的两处落地；另外服务端有 `PA_MCP_READONLY=1` kill switch 可整体撤写面。
4. 版本协商规则：请求的版本在支持列表里就回显，不在就回自己支持的最新版。请求 2024-11-05（在支持列表里）→ 回显 2024-11-05；请求 1999-01-01 → 回 2025-06-18。好处：老客户端知道你还支持它的版本，协议演进不把旧客户端锁死。
5. one-shot 管道调试（echo 一行 | 服务器）时 stdin 立刻 EOF，readline close——如果立即 `process.exit`，在途的异步应答（kb_search 要先读文件）还没写完就被截断，调试者什么都看不到。`pendingCalls` 记录在途调用数，close 时 `while(pendingCalls>0) sleep(50)`（上限 30s）排干再退。真实客户端从不发完请求立刻关 stdin，这个等待只发生在管道场景，不改变正常关停语义。
6. 第一版用 `spawn + stdio:'inherit'`，Windows 上子进程的 stdout 应答在管道场景整条丢失（stderr 透传正常）——spawn 加一层进程，stdout 继承有平台怪癖。改 in-process `import { main }` 直接跑：stdin/stdout 就是命令自己的，协议通道天然干净，还省一层进程和退出码转发。
