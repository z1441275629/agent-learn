## 2. 核心知识讲解

### 2.1 langChain 中间件：wrap 系 vs before/after 系 + 改 state 的通道形状

自定义 middleware 是 langChain 里扩展 agent 行为的主通道，但改 state 有严格的通道纪律（PITFALLS #66）：

- **三类钩子分工**：
  - **wrap 系（wrapModelCall / wrapToolCall）**：管**执行拦截**——包住底层调用，可以在调用前/后注入逻辑（如重试、纯观察 usage、注入参数）。工具执行结果必须经 `Command.update` 回写，且**必须自带 messages 字段**，否则工具结果会静默丢失。
  - **before / after 系（beforeModel / afterModel / beforeAgent / afterAgent）**：管**状态补丁**——在模型调用前后读写 state，适合计数、校验、跳转决策，不做调用拦截。
  - **channel / ReducedValue**：跨调用**累加**的通道。`record` + `thunk` 默认值模式：`ReducedValue` 会在每次工具调用后自动把增量累进 state，且对快照只读、不改原始 messages。
- **数组顺序 = 包装顺序（洋葱模型）**：middleware 数组按顺序层层包住，先注册的在最外层。HITL 必须裹住 retry——这样 HITL 的暂停才能拦住 retry 的自动重试；顺序写反，retry 会把本该等人类审批的调用自动重试掉。
- **jumpTo 白名单**：afterModel 里发现「无工具收尾且未记笔记」时，不能直接改输出，要走 `canJumpTo` 白名单里的节点 `jumpTo` 弹回 model 强制补一轮 write_note，且只提醒一次防死循环。

### 2.2 LangSmith 零代码 tracing 与「OpenAI 兼容端点」桥接

- `LANGSMITH_*` 环境变量配好后零代码 tracing：agent 的每次模型调用、工具调用、中间件事件自动成树，网页可看，是排查 agent 行为的免费调试器。
- OpenAI 兼容端点**不能**走 provider 前缀字符串（如 `gpt-4o` 那种 `openai/xxx` 命名），前缀只认框架固定命名的环境变量；自定义的 `LLM_*` 三件套（baseURL/key/model）要靠 `fromEnv` 工厂显式桥接，按主/轻/备三档建实例、key 回落链照 .env 注释语义。

### 2.3 LangGraph 状态机：条件边 / Send / 子图，通道语义三层

一张图三个新零件，每个都对照手写实现：

- **条件边 = 单路选择，Send = 并行 fan-out**：条件边函数返回下一个节点名（路由三态就是一条 `addConditionalEdges`）；Send 返回一批「节点名+专属输入」，同批任务同一 superstep 并行跑、全部完成后下一跳的 merge 跑一次（map-reduce 的 map/reduce）。关键纪律：**Send 的输入是快照**——被 fan-out 的节点不读共享 state，每次调用拿显式给的 `{step, question}`，节点间无共享内存、交接必须显式（手写 PARALLEL 的 Promise.all 对照：并行从节点内部升进图拓扑，框架管批调度）。
- **通道写入有三层防线**（探针①实证的顺序）：①入口校验——update 值先过字段 schema（类型不符当场拒，到不了 channel）；②归并语义——合法值进 channel 时按 reducer 合并，无 reducer 字段是 LastValue 一步只收一个值，同 superstep 两笔合法写入直接 `InvalidUpdateError`（错误原文会把冲突双值都打出来）；③框架的设计立场——**拒绝静默覆盖**：手写 Promise.all 并发写互相覆盖是隐性竞态静默出错，LangGraph 用硬错误逼你声明归并语义。所以并行写的聚合点必须是 reducer channel；`ReducedValue` 的 `inputSchema` 支持「存数组、写单条」（append 账本同构，节点 update 传 string、reducer append）。
- **子图 = 编译好的图直接当节点**：父子图的交接面是**两边 schema 的同名 keys**（messages/draft/verdict/revisions/note）——显式契约不是隐式全局；修订循环是条件边回边（review→FAIL 未熔断→revise→review），熔断就是回边条件里的计数判断（`revisions >= 2` 放行出图）。

### 2.4 图拓扑确定、判定节点不确定（#67：判定参数按判断类型配）

条件边和熔断给的是确定性**拓扑**，但路由/审校是图里的 LLM **判定节点**——非确定性的注入口；拓扑的确定性到第一个未锁参数的判定节点为止：

- **直觉判断**（路由这种单发分类）：温度 0 + 思考关——快且稳；
- **逐条核对型判断**（审校核事实）：温度 0 + 思考低档——flash 级判官关思考会产噪声判定（#61 的坑，换层复现）；
- **产出节点**（写手/研究员/规划器）：默认参数——产出要多样性、判定要稳定性，**两类节点参数策略相反**，所以一张图两套模型实例；
- 非标参数（thinking/reasoning_effort）经 `modelKwargs` 直通，对照 pa `thinkingParams()` 的 openapi 形态；温度 0 不是逐位确定（服务端批处理/MoE 微扰仍在），杀掉的是「首跑误路由、时过时打回」量级的漂移。

## 4. 参考答案

1. **wrap 系**管**执行拦截**：包住底层真实调用，可在调用前后注入逻辑（重试、观察 usage、改参数），工具调用后必须用 `Command.update` 回写结果且自带 messages，否则结果静默丢失。**before/after 系**管**状态补丁**：在模型调用前后读写 state，适合计数、校验、跳转决策，不拦截底层调用。场景：重试/成本观测用 wrap，计数/收尾校验用 after。
2. 中间件按数组顺序层层包装，先注册的最外层、后注册的最内层。HITL 必须裹住 retry：否则 retry 先重试完才轮到 HITL，本该暂停等人类审批的 flaky 调用会被自动重试掉，审批失去意义。顺序 = 包装顺序，写反了行为就反了。
3. `ReducedValue` 是跨调用自动累加的 channel：`record` 记录增量、`thunk` 提供默认值，每次工具调用后框架自动把增量累进 state。相比手动改 state，它天然对快照只读、不会污染原始 messages，且省去手动「读→改→写回」的样板代码。
4. 三件事：①计数用 `ReducedValue` 的 channel（record + thunk default），每次工具调用自动 +1；②工具结果必须走 `wrapToolCall` + `Command.update` 写 state，且 command 里必须带 messages；③afterModel 检查「没有工具调用且没记笔记」时，不能直接改输出，而是经 `canJumpTo` 白名单 `jumpTo` 弹回 model 强制补一轮 write_note，并用一个已提醒标志只提醒一次、防 A→B→A 死循环。这就是 A/B/C 约束阶梯：A 靠提示词、B 靠交付绑定、C 靠中间件硬门。
5. 记账拆两段：`wrapModelCall` 在调用返回时**纯观察** response 里的 usage（token 数），不改任何东西、不拦调用；`afterModel` 里用 `ReducedValue` 把本次 usage **增量累计**进 state 的账本字段。观察和累计分离：wrap 只管拿数据，after 只管入账，账本字段随每次调用自动累加，最后统一读账本即总成本。
6. **条件边是单路选择**（返回一个节点名，路由分发）；**Send 是并行 fan-out**（返回一批「节点+专属输入」，同 superstep 并行、下一跳单次 reduce，map-reduce 的 map）。纪律：被 Send 的节点**不读共享 state**，输入是显式给的快照——节点间无共享内存，交接必须显式；并行写的聚合字段必须是 reducer channel，否则同 superstep 多写直接 InvalidUpdateError。
7. 四态：**approve**（原样执行）/ **edit**（人工改工具名或参数后执行）/ **reject**（不执行，拒绝理由回给模型）/ **respond**（人工直接替工具作答）。还有 batched（一轮一张审批卡）和 per_call（每个调用一张带 responseSchema 的卡）两种模式。pa 确认门只有放行/拒绝两态且 fail-closed（无门、超时、断流一律拒绝）——框架给了暂停点，**放行策略是接入方的信任决策**：不确定时收窄决策面比敞开四态更安全，edit/respond 都是人工替模型做主的通道，没有严格身份校验就不该开。
8. 三个理由：①Send 并行的 N 个 exec 都要写 results，聚合点必须是 reducer channel，裸字段（LastValue）一步只收一个值，两笔合法写入直接 `InvalidUpdateError: LastValue can only receive one value per step`（错误原文带冲突双值）；②`inputSchema: z.string()` 让节点 update 只传单条 string、reducer 负责 append——账本 append 语义的框架原生表达；③写入有三层防线：入口校验（值过 schema，类型错当场拒）→ 归并语义（合法值进 channel 撞 reducer/LastValue 规则）→ 框架拒绝静默覆盖（手写 Promise.all 并发写是隐性竞态，框架用硬错误逼你声明归并语义）。
9. 子图先独立 `new StateGraph(CompositeState)...compile()`，编译产物**直接当主图节点** `.addNode('composite', composite)`；交接面 = 两边 schema 的**同名 keys**（messages/draft/verdict/revisions/note），显式契约不是隐式全局。修订循环是条件边回边：review 之后 `(s) => s.verdict === 'PASS' || s.revisions >= 2 ? 'done' : 'revise'`——FAIL 且未熔断走 revise→review 回边，PASS 或 `revisions >= 2` 出图；熔断就是回边条件里的计数判断，对照 pa composite 的修订熔断 ≤2 轮。
10. 因为一张图里有三类节点、参数策略相反：**routerLlm**（直觉判断，单发分类）温度 0 + 思考关——不锁会首跑误路由；**judgeLlm**（审校，逐条核对）温度 0 + 思考低档——flash 判官关思考产噪声 FAIL/PASS（#61 的坑换层复现）；**llm**（research/revise/planner/exec 产出节点）默认参数——产出要多样性。原则：确定性编排止于第一个未锁参数的判定节点，图管路径形状、判定节点参数管路径本身；非标参数（thinking/reasoning_effort）走 `modelKwargs` 直通，和 pa `thinkingParams()` 同一形态。
