## 2. 核心知识讲解

### A. 流式多通道：谁是全量、谁是增量、翻译层为什么必须有

**是什么**：LangGraph `stream()` 可选通道组合——`values` 每 superstep 吐**全量** state（适合回放、审计、最终态对账）；`updates` 只吐**本步谁写了什么**（适合进度条、调试、token 记账）；`custom` 是业务事件通道（`getWriter()?.({...})` 手动发，载荷自由）。messages 通道则吐 token 级 `AIMessageChunk`，chunk 自带 `langgraph_node` 标签。

**为什么**：不同消费者要不同粒度——前端要 token 级 delta，进度面板要节点完成事件，审计要全量。单通道混流（pa 的做法）靠 type 字段应用层自分流；多通道把分流下沉到框架，每项自带通道标识，交错到达也不用消费端排序。

**怎么用（SSE 桥）**：翻译层把 (通道, chunk) 映射成 pa 风格帧——`AIMessageChunk.content`→delta 帧 token 级透传；`instanceof ToolMessage`→tool 帧（messages 通道里混着**完整** ToolMessage，不能只按 chunk 形状判）；custom→原样进帧；图结束→done 收口。前端 ReadableStream 按 `\n\n` 切帧。断线重连：无 text 帧 = 有 interrupt 挂起，重连补发挂起题面（题面可从 state 重建）——S6 handoff「无收口人」的流式全量回放方案，底座就是 chunk 带 `langgraph_node` 标签的归档。

**和什么相关**：pa SSE 单通道 type 分流；生产客服「转人工回放上下文」同构；#75/#76 都是流管道里静默坏数据——见 B。

### B. 静默失败家族：#75 静默垃圾 / #76 静默空事件（#71/#74 同族）

**是什么**：框架边界处数据坏了但**不炸**，坏数据沿管道流到下游（模型/前端/评估器），表象出现在下游、锅在边界。今天连踩两个：#75 是 JS 类型系统静默强转（`String(Promise)` 产出合法字符串垃圾）；#76 是两套事件系统不通 + 可选链吞 undefined（发了个寂寞，零异常）。

**为什么比异常难一个量级**：报错自带方向（栈 + 消息指到出错行）；静默失败只有下游表象（模型说工具坏了 / 前端没事件 / #74 的 0 分实验照常跑完），要反向溯源到边界，且每一步都「正常」。

**方法论（两案共同的路数）**：
1. **源码定位接线点**——#76 翻 writer.js / config.js / index.js 三处，确认 writer 挂在顶层 `config.writer` 而导出读 `configurable.writer`；
2. **零 token 探针实证姿势差异**——三姿势各发一条（getWriter() 与节点 config.writer 各进一条、writer() 导出零条），不靠猜；
3. **消费端验收**——事件/流这类无对账机制的系统，「发送方说发了」不算数，「消费端收到帧」才算数（jobprep 的 SSE 桥直接按这条验收）。

**和什么相关**：fail-fast 不 fail-lost（S5：ZodError 照炸但 checkpoint 不推进，resume 可救回）；判定要锁参数（#67）；当天闭环——上午立的 #76 姿势，下午 jobprep 事件外发直接用对。

## 4. 参考答案

1. `values`：每 superstep 后全量 state 快照，越滚越大——回放、审计、最终态对账；`updates`：本步节点名 + 写入差集——进度、调试、按节点记账；`custom`：业务事件，载荷自由——前端 UI 通知。不需要消费端排序：多通道流每一项自带通道标识，分流是框架级的（对照 pa 单通道混流要在应用层用 type 字段自分流）。

2. dispatchCustomEvent 属于 @langchain/core 回调系统（streamEvents 的 on_custom_event 消费），与 LangGraph 的 custom 通道是**两套系统**不互通；`writer()` 导出只读 `configurable.writer`，Pregel 却把 writer 挂顶层 `config.writer`，可选链 `?.` 拿到 undefined 静默返回——零异常零事件。预防：①事件/流这类无对账机制的层，验收必须到消费端（收到帧才算通）；②跨版本 API 跟当前源码核对接线点，用官方当前姿势（`getWriter()?.()`）；③家族意识——静默失败（#71 resume 空转 / #74 静默空 / #75 静默垃圾）共性是边界坏了不炸，见到「下游表象怪、上游全正常」先怀疑边界。

3. `tool()` 返回 Runnable 不是原函数，invoke 契约永远异步——同步实现也包 Promise。不 await 就进字符串拼接，JS 静默强转成合法字符串 `"[object Promise]"` 喂给模型。难的是**方向缺失**：异常自带栈和消息（方向现成），静默垃圾表象在下游（模型行为异常、重试、道歉），锅在上游边界——本例模型三次重试后说「工具坏了」，它对自己收到的输入诊断完全正确，错的是人以为工具坏了。Runnable 系工具（tool() 包装、agent.invoke）手动执行时 await 是共同边界。

4. 翻译层职责 = 通道→帧型映射：messages 通道 `AIMessageChunk.content`→delta 帧（token 级透传）；`instanceof ToolMessage`→tool 帧——messages 通道混着完整 ToolMessage，chunk 判别式不可靠，必须类型判别；custom→原样进帧；图结束→done 收口。粒度对齐 pa 的 onText/onToolCall（翻译层两头都是既定协议，不发明新粒度）。断线重连：SSE 收不到 text 帧 = 图在 interrupt 挂起等人作答，重连时从 state 重建当前题面补发（pick_question 是纯函数、题面在 state 里可重放），S8 底盘直接复用到 jobprep。

5. 三段各治一个坏模式：错题优先 = 间隔复习闭环（弱点统计反哺抽题）；排除刚问 = 防连续重出同一题（体验坏模式）；耗尽全库随机 = 兜底，永不空转。BM25 预留给「大题库语义抽题」，P1 题库 45 题——均匀性 > 语义相关性，纯函数策略 vitest 直测、成本近零：按真实需求上强度，不提前支付复杂度。判官温度 0（#67 判定节点锁参数）：批改要稳定可复现，同答案两次评分一致；锚定参考答案 + structured 输出（hits/misses）防自由发挥，批改结果可对账——产出节点要多样性，判定节点要稳定性。
