## 2. 核心知识讲解

### ① 编排的可靠性设计：机械闸 + fail-closed + abort 归因 + 输出契约

- **是什么**：让多角色编排（研究→审校→写作→审校→落盘）在模型不配合时也能收敛、不崩、不产生脏产物的一套机制，外加用**输出契约**约束模型产出的形状与颗粒度。
- **为什么**：子 agent（研究员/检索）在 ReAct 循环里会**一直调工具不收尾**——模型没有「该停了」的自觉；编排链一旦某环空产出或误判，要么死循环烧 token，要么把用户中止当系统错误记进账本，要么产出编造内容；而审校环节若思考开满，会把「通过项」也判成 FAIL 产生噪声，拖低一次通过率。
- **怎么用**：
  - **机械终止闸**：runToolLoop 加 maxCalls（4~8），超限**强制**提取最后文本出结果，不依赖提示词自觉（PITFALLS #54）。
  - **fail-closed 解析**：parsePlan / parseCriticVerdict 首行锚定 + 解析失败一律回落安全路径（planner 失败回落单 agent，审校判不出就当不通过），绝不猜。
  - **abort 归因**：非流式单发调用被用户中止时抛 AbortError，catch 里**先查 signal.aborted 再谈错误**，归因 aborted → chat 落盘 interrupted，不误标 error（PITFALLS #53）。
  - **空产出兜底**：闸断后模型可能只吐 reasoning 不吐正文，机械合成「素材不足」简报喂给审校去判，编排不崩。
  - **输出契约**：审校思考开低档（无思考逐条核对，避免通过项占 FAIL 行的噪声判定）；评审输出只列真违反项、边缘按通过（issue 纪律）；简报契约 4~8 条、每条 2~3 句带具体事实（素材厚度喂饱写手，从源头防编造）；写手提示词内嵌审校判据 + 交稿前自检（把判据前置到写作环节，提高一次通过率）。
- **和什么相关**：与之前 MCP 层的「错误两层」（协议错 vs 执行错）同一哲学——**把模型当不可靠组件，用机制兜底，不靠自觉**。

### ② ReAct token 经济学：为什么 6 次调用烧 6 万 prompt

- **是什么**：一次研究任务 6 次 LLM 调用烧掉 6 万 prompt token 的现象与对策。
- **为什么**：ReAct 循环每轮把**全部历史结果**（工具返回、中间思考）重发给模型做上下文，轮次越多单轮 prompt 越长——**开销是累加的**，不是每次调用独立计费。根因是「每轮重发全部历史结果」，不是「思考本身贵」。
- **怎么用**：
  - **源头截断**：工具结果在进上下文前就截断（maxResultChars 9000→3000），别等模型自己取舍。
  - **收紧机械闸**：maxRounds 4→3、maxCalls 6→4，减少轮次即减少重发次数，提示词终止纪律同步。
  - **护栏可调**：整篇护栏 60k→90k 放 env，给长主题留余量。
  - **成本账全覆盖**：路由/规划层自身的 LLM 调用也要记 usage 进成本账（PITFALLS #60），别只算子 agent。
- **和什么相关**：与之前「上下文压缩（超预算旧轮交摘要落盘）」同源——**token 预算是编排的第一公民**，从源头和轮次两头掐。

## 4. 参考答案

1. **机械闸 vs 自觉**：模型没有「该停」的自觉——检索子 agent 在 ReAct 循环里会一直调工具不收尾，靠提示词「请收尾」不可靠（实测失效）。实现：runToolLoop 加 maxCalls 机械计数（研究段 4、执行段 8），超限**强制**提取最后一轮文本作为结果返回，不再等模型自己收尾；配套提示词终止纪律（「素材够了就停」），但机制兜底不靠自觉。digest 同理：闸断后模型可能只吐 reasoning 不吐正文，机械合成「素材不足」简报喂给审校判，编排不崩。
2. **abort vs 错误**：用户中止是**主动取消**，系统错误是**被动故障**，两者语义不同——记错账本会让「用户中止」显示成「系统 error」，污染可靠性统计。区分：非流式单发调用被中止时抛 AbortError，catch 里**先查 signal.aborted**（或错误类型判断），是则归因 aborted，chat 据此落盘 interrupted；否则才按系统错误归因。顺序不能反：先查信号、再谈错误。
3. **忠实性判据**：写博客是「把简报（事实）转成文章」，具体值（路径/文件名/日期/数字）是最容易编造也最容易核验的部分——没有简报依据的值一律判不通过，从根上堵编造；正则/代码是读者会直接复制执行的，简化到语义改变等于误导。**审校低档更准**：逐条核对是机械比对任务，开满思考反而产噪声——模型会把「通过项」也脑补出理由判成 FAIL（通过项占 FAIL 行），无思考（flash）逐条比对反而干净；配合评审输出契约（只列真违反项、边缘按通过）进一步降噪。
4. **token 累加**：ReAct 每轮把全部历史结果重发给模型做上下文，第 n 轮 prompt ≈ 前 n-1 轮全部产出 + 本轮，开销随轮次**累加**，不是每次独立计费——6 次调用烧 6 万就是重发历史堆出来的，不是「思考贵」。掐两头：**源头**——工具结果进上下文前截断（maxResultChars 9000→3000）；**轮次**——收紧机械闸（maxRounds 4→3 / maxCalls 6→4）减少重发次数；护栏 60k→90k 放 env 给长主题留余量；别忘了路由/规划层自身调用也记 usage（PITFALLS #60）。
5. **runBlogComposite**：入口是规则触发路由（零 token，问句拦截），composite 模式走编排：①研究员（只读子 agent，优先 git_log/read_file 取材，报不存在的文件不重试）→ ②审校①素材审查（parseCriticVerdict 首行锚 + fail-closed）→ ③写手（提示词内嵌审校判据 + 交稿前自检 + 结构差异化）→ ④审校②忠实性审查（具体值必须有简报依据）→ 修订熔断 ≤2 轮，超限按当前最优过或判不通过；全程成本护栏（单步 maxCalls、整篇 90k 上限 env 可调）+ abort 归因（先查 signal）；过审稿确认后落盘 blogs/账本/done 帧；标题/slug 纯函数；chat 路由里 composite 模式走编排、normal 原样。
6. **planner 三态到执行**：路由先判——≥2 去重动作词+连接词 → plan（多步优先于博客触发，无连接词的双词不误拦；真实消息回归 8/8）；问句走 normal 主路径。触发后规划师小档单发严格 JSON 步骤表（≤4 步，goal 自包含 + 能力二选一：blog / agent），parsePlan 剥围栏/归一，解析失败 fail-closed 回落单 agent（null 兜底）；执行器 runPlan 步骤串行：blog 步委托博客编排（链内落盘门），agent 步子 agent 全套工具 + 技能自动注入 + 确认门透传；步骤间以**仓库产物 + 600 字摘要**衔接；整链 CEILING(env 100k) + 每步 maxCalls 8 + abort 归因 + 空产出兜底；规划师自身 token 通过 PlanOutcome 并进 usage 账（PITFALLS #60 的修复点）。断言 20/20。
