# 模块 11 · 生产工程——evals / 可观测 / 安全（demo 与产品的分界线）

> 定位：前十个模块回答「怎么让 agent 干活」，这个模块回答「怎么敢让别人用」。
> 被测系统现成：模块 10 的组合产线（composite.ts）——真实输入（素材）、真实中间产物（简报/稿件）、
> 真实失败形态（短路/熔断/违约），不用造玩具。

## 0. 定位：demo 与产品的分界线

- demo：能跑一次给你看；产品：跑一万次都知道会发生什么
- 三根支柱：**evals**（改了东西知道变好还是变坏）、**trace**（出了事能逐帧回放）、**安全**（别人可以使坏时它死不了）
- 核心问题：评测集怎么建才不是「自己考自己」？judge 的偏差怎么控制？间接注入为什么防不绝、只能纵深防御？
- 表达点：「我的 agent 项目有评测集和全链 trace」——这一句就能和 90% 只写过 demo 的候选人区分开

## 1. evals：评测集怎么建才不是「自己考自己」

- case 从哪来：产线的真实运行（全料/薄料/短路三态都是 case）——不是拍脑袋编的
- 期望怎么写：黄金输出 vs 性质判据（rubric）——**为什么抄模型自己的输出当标准是循环论证**
- TODO ① 建第一版评测集：N 个 case + 每 case 的可判性质
- TODO ② 跑分器：性质判据自动判——免费的先判（形状/出处/数字，digestCheck 的经验直接用），语义的留给 §2 的 judge

## 2. LLM-as-judge：judge 的偏差与控制

- judge 就是 §6/§7 的 critic 换岗位——模块 10 的教训直接带岗：判据需要什么交接物就给什么、锚钉死、fail-closed
- 偏差三连：**位置偏差**（先看的打分高）/ **自我偏好**（同模型夸同模型）/ **严松漂移**（跑十次给分不一致）
- 控制法：成对比较替代绝对打分 / judge 换模型（和被测不同源）/ 抽查人审对账
- TODO ③ judge 上岗 + 对账一次：judge 判 vs 你人判，算一致率——不一致的 case 就是 judge 的药

## 3. 手写最小 trace：把 [账] 流水升级成结构化追踪

- 现状：[账] 是 console.log，跑完就没了——§8 的流转图靠手填
- 目标：每次运行一份 trace 落盘（span 树：每次 spawn 一个 span 含 token/耗时/结论摘要/verdict，门检/parse 记零成本事件）
- 回头债自动清：**流转图从 trace 生成**，不再手抄

## 5. 攻：prompt injection 实攻——先攻破自己一次

- 直接注入：用户输入里藏「忽略以上指令」——demo 级，练手
- **间接注入（重点）**：工具返回/素材里藏指令——产线的注入面就是 SOURCE_MATERIAL 和 handoff 交接物
- 目标：**真攻破一次**（让产线输出攻击者想要的东西/泄漏不该漏的内容），完整记录载荷与被劫持路径
- TODO ⑥ 构造注入载荷 + 实攻记录（被劫持到哪一步、烧了多少 token）

## 6. 防：纵深防御——为什么防不绝、只能纵深

- **指令/数据分离**（软）：交接物里的内容不构成指令——delimiters 钉死 + 角色重申
- **工具最小权限**（硬）：§10 工具面白名单复用——被劫持了也摸不到危险工具
- **输出审计**（硬）：交付前扫一遍——泄漏/越权指令的形状
- TODO ⑦ 防住 §5 的载荷 + 换个载荷再攻一次验证 + 诚实记录防不住的部分（防不绝是结论不是失败）
