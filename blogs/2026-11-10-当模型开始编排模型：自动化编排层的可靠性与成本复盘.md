# 当模型开始编排模型：自动化编排层的可靠性与成本复盘

模块16的主题是自动化编排层。今天做的事可以概括为：让多个智能体协作完成博客写作，并且让这条链路可预期、可计量。上午打通了「研究→审校①→写手→审校②→落盘」的整链；下午在此基础上叠加了多步 planner，把「路由三态→规划师→执行器」串起来。贯穿始终的两条主线是**可靠性与成本**。机制全部落在 `personal-agent/core/router.ts` 与 `composite.ts` 两个源文件里，当天关键提交从 `4395075` 到 `448db09` 共 19 条。

这篇复盘按工程主线展开：入口怎么零成本分流、planner 怎么把拆解从模型自觉变成协议、token 为什么会失控、以及最后用哪几套护栏兜底。

## 入口闸门：三个正则，零 token 分流

路由层是整条链的入口，原则很朴素：**能用正则判断，就不消耗 token**。`router.ts` 里三个正则按顺序做判断：

- 先拦问句：`QUESTION_MARKERS` 匹配 `(怎么|怎样|如何|为什么|吗|？|\?|是什么)`，命中即按普通问答处理；
- 再判计划：出现不少于两个去重动作词，并命中 `PLAN_CONNECTORS` `(并|然后|再|之后|接着|同时)`，走 plan；
- 最后查创作：`COMPOSITE_TRIGGERS` `(写|生成|出).{0,25}(博客|技术文章|文章)`，命中走 composite。

全部纯正则，不依赖模型自觉。这里有一个非常典型的教训：间隔窗口最初是 `.{0,15}`，但实测 `写一篇关于funciton calling的博客` 里「写」到「博客」相隔 21 字符，曾被漏触发；所以放宽到 `.{0,25}`。路由这种零成本入口，正则细节直接决定任务会不会静默降级。

## 两段式 Planner：拆解从模型自觉变成协议

多步任务不是让模型临场发挥，而是拆成「规划师 + 执行器」两个角色：

- **规划师**：小档模型单发，输出严格 JSON 步骤表。步骤数上限 4；每一步的 `goal` 必须自包含、能力只能在 blog / agent 二选一。`parsePlan` 负责剥围栏、归一化，并 fail-closed——解析失败或调用返回 null 时，直接回落单 agent，而不是硬着头皮执行。这部分断言 12/12。
- **执行器**：`runPlan` 把步骤串行跑起来。blog 步骤委托给博客编排链；agent 步骤拉起子 agent，全套工具和技能自动注入，确认门透传。步骤之间用仓库产物加一份 600 字摘要衔接，保证上下文不丢。整条链以环境变量可调的 100k 作为 token 天花板，每步 `maxCalls` 8，abort 归因，空产出有兜底。这块断言 20/20。

关键设计是：**拆解结果不是模型嘴里的一句话，而是一份可解析、可回落的 JSON 协议**。

## ReAct 的账单：六次调用烧六万 prompt

今天最值得记的一笔账是：**6 次调用烧掉 6 万 prompt token**。根因不是「思考贵」，而是 ReAct 每轮都会把全部历史结果重发一遍，上下文随轮次累加——第 6 轮时，前 5 轮的结果全部重新计费。

对策分三层：

- **源头截断**：研究段 `maxResultChars` 从 9000 调到 3000；
- **机械闸收紧**：`maxRounds` 从 4 调到 3、`maxCalls` 从 6 调到 4；
- **整篇护栏**：从 60k 放宽到 90k（环境变量可调）。

组合起来一句话：与其在循环里省单轮成本，不如在入口和轮次上做硬限制。

## 可靠性三件套：不靠模型自觉

模型在循环里随时可能失控，所以三套硬机制兜底：

- **机械终止闸**：`runToolLoop` 加 `maxCalls`，超限后强制提取最后文本作为结果。PITFALLS #54 印证了这一点——靠提示词让模型自觉停止不可靠。
- **fail-closed 解析**：`parsePlan`、`parseCriticVerdict` 都做首行锚定，解析失败就回落安全路径，不把脏数据往下游传。
- **abort 归因**：非流式单发调用被中止时抛 `AbortError`，catch 里先查 `signal.aborted` 再谈错误，归因记为 `aborted`，chat 落盘记为 `interrupted`。PITFALLS #53 记录的就是编排内部 catch 曾把用户中止误归因成系统错误。

## 收敛与落盘：composite.ts 里的熔断护栏

编排链的收敛保障在 `composite.ts` 里可见：

- **修订熔断**：最多 2 轮，超过即熔断；
- **成本护栏**：超限即终止；
- **abort 三件套**：同上；
- `stoppedBy` 枚举记录结束原因，区分 6 种：`done | research-melt | writing-melt | cost-guard | aborted | error`。

还有一个很实的兜底：digest 闸断后，如果模型只吐 reasoning 不吐正文，编排不会崩，而是机械合成一份「素材不足」的简报交给审校判定。

标题和 slug 全部走纯函数：`titleFromBlog` 取首行去掉 `#`，`sanitizeSlug` 清洗非法字符并截断 40，`slugPathFor` 生成 `blogs/YYYY-MM-DD-<slug>.md`。

## 质量防线：把判据前置到写作环节

一次通过率不是靠审校时严格，而是把判据往上游推：

- **审校思考档位调低**：flash 无思考模式做逐条核对反而更准；开启思考时，通过项也会占据 FAIL 行列，产出噪声判定。
- **写手提示词内嵌审校三条判据**（忠实性、完整性、针对性），交稿前自检，把判据前置到写作环节。
- **简报契约改为 4~8 条、每条 2~3 句且带具体事实**——素材厚度喂饱写手，从源头防编造。

另外，审校的忠实性判据补了两处盲区：代码/命令示例里的具体值（路径、文件名、日期、数字）必须有简报依据，编造即不通过；笼统的技术表述要与简报机制一致——当天成稿曾漏掉一个编造的 2025 日期，也曾把 BM25 误述成「语义匹配」。

最后一条正则教训：触发正则的间隔窗口要留余量，长主题名会撑破窗口导致静默降级，记入 PITFALLS #55。

## 总结

把今天的 19 个提交压缩成一句话：**先让入口零成本分流，再把任务拆解变成协议，然后用机械闸、fail-closed 和 abort 归因对抗模型的不确定性，最后在质量和成本上各加一道护栏**。

可靠性与成本不是两个并列的目标，而是同一个工程系统的两面——路由层选正则是为了零成本，planner 选 JSON 协议是为了确定性，ReAct 的截断和轮次限制是成本账，复合编排的熔断是可靠性账。当模型开始编排模型时，最重要的不是提示词写得多好，而是每一步都有退路。
