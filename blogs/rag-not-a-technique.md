# RAG 不是一种技术，是一族技术

假设期末考试允许翻书。你是选择把整本教材背进脑子，还是带着参考书进场，遇到不会的题现场翻书？对 LLM 来说，这是两条完全不同的知识注入路线：

- **微调（PEFT / KD）**：把知识写进模型参数。相当于闭卷考试，效果扎实，但每次更新知识都要重新训练。
- **上下文学习（ICL）**：在 prompt 里现场给几个例子。相当于带小抄进考场，轻量，但受上下文窗口限制。
- **RAG**：先检索外部知识库，再结合检索结果生成。这才是真正的开卷考试——教材放在手边，随查随用。

RAG 近年火，不是因为它比微调「更聪明」，而是因为它把知识从模型参数里解耦出来：知识库还是那个知识库，模型还是那个模型，只是回答前多了一步「翻书」。但「翻书」这两个字，其实掩盖了大量设计空间——翻哪本书、怎么翻、翻到的书质量不行怎么办、甚至要不要先判断一下「这道题需不需要翻书」？对这些问题的不同回答，长出了一整族 RAG 技术。

## 一、RAG 本体：「检索 → 生成」的最小闭环

RAG 的基础流程是一条清晰的四步链路：

1. **知识库切片**：知识库太大，整本塞给模型不现实。先把知识切成适当大小的片段，便于之后精准检索。
2. **向量化**：将切片内容向量化，存入索引。文本从此变成可计算相似度的向量。
3. **检索**：用户提问后，将问题向量化，在知识库索引中检索最相关的片段。
4. **生成**：把检索到的片段和原始问题一起交给大模型，由模型生成回答。检索结果成了模型作答的「参考书」。

这是最基础的 RAG，也是「开卷考试」最简单的实现：题库事先建好索引，考试时按题查资料，然后作答。但每步都有优化空间——于是有了下面这些变体。

## 二、RAG 家族：五种解决不同问题的方案

| 形态 | 关键机制 | 解决的痛点 |
|---|---|---|
| RAG | 检索一次、生成一次 | 基础开卷考试 |
| Agentic RAG | 检索变成模型可多次调用的工具 | 复杂问题需要反复查证 |
| CRAG | 检索质量差时触发修正 | 翻到的书不可靠 |
| Self-RAG | 模型自评「要不要检索」 | 不是所有问题都值得翻书 |
| GraphRAG | 用知识图谱组织文档关系 | 文档之间存在复杂关联 |

逐条展开：

**RAG**：基础款。一次检索，一次生成。适合知识库结构简单、问题和答案片段对应明确的场景。

**Agentic RAG**：把「检索」从固定步骤升级成模型可调用的工具。模型自己决定什么时候查、查几次、要不要换关键词再查。适合多步骤推理或需要交叉验证的问题。

**CRAG**：针对检索质量差的兜底方案。不是所有检索结果都可靠，当检索到低质量内容时触发修正，而不是硬着头皮用坏结果生成。

**Self-RAG**：把决策前移——模型先自评「这个问题需不需要检索」，再决定走检索还是直接生成。有些常识问题，翻书反而是多余的。

**GraphRAG**：不用向量索引组织知识，改用知识图谱表达文档之间的关系。回答问题时，不仅能找到孤立片段，还能顺着图结构拿到上下文关联。

这五种不是互相替代，而是同一套「开卷考试」规则下的不同策略。选哪种，取决于你的知识库长什么样、要回答的问题有多复杂。

## 三、怎么衡量 RAG 好不好：检索与生成，分开看

RAG 的评估可以分两层：检索层回答「有没有翻对书」，生成层回答「有没有写好答案」。三个常用指标：

- **Hit Rate（命中率）**：检索出的结果里，有没有包含正确答案。衡量「覆盖」。
- **MRR（Mean Reciprocal Rank）**：正确答案排名的倒数取均值。检索结果里有正确答案，但它排第 10 位和排第 1 位，体验完全不同。
- **RAGAS**：RAG 专项评测框架，覆盖忠实度（生成是否忠于检索证据）、相关性（检索结果与问题是否相关）等维度。

注意一个视角：Hit Rate 和 MRR 评的是检索侧，RAGAS 评的是生成侧。很多 RAG 系统「书翻对了，但答案写得不行」——这时候调检索没用，得看 RAGAS。

## 四、两个容易踩的坑

最近一次审校记录里，有一篇 RAG / BM25 相关的成稿被打回。两个盲区值得单独拿出来说，因为它们都很隐蔽：

**坑一：BM25 不是语义匹配。** BM25 是经典的关键词检索算法，在型号、代号、人名这类精确匹配场景下表现很强。但它做的是词法匹配，不是语义匹配。经常有人顺手把 BM25 描述成「语义检索」——错。BM25 和向量检索是互补的：一个精于精确匹配，一个精于语义召回。

**坑二：没有来源的数字不要写。** 技术博客里很容易顺手写「实验效果提升 30%」「2025 年发布的新方法」这类陈述。如果没有一手依据，这都属于编造。审校对代码、数值、日期的要求是「必须有依据」——没有一手来源，宁可只写机制，不写数字。

## 总结

回头看，RAG 的价值不只是「先检索再生成」这六个字，而是它把「知识」从模型内部解耦到外部知识库。模型不必闭卷硬背，知识更新也不必重新训练。这等于给所有 LLM 应用开了一场「开卷考试」。

而开卷考试的形式还在演进：每一题都翻书（RAG）、考场上见机行事地翻书（Agentic RAG）、翻到烂书就换（CRAG）、先判断要不要翻书（Self-RAG）、按知识图谱翻书（GraphRAG）。选哪套方案，取决于你的考场长什么样。

最后提醒一句：不管选哪套 RAG，先想清楚怎么测量「翻书」的效果——Hit Rate、MRR、RAGAS，总得选一个。
